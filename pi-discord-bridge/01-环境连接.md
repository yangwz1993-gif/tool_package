# 01 环境连接

换一台新电脑，把 pi 和 Discord 重新连起来。

这一篇只管「装好、连通、能跑」。建子区和日常操作在 [02](02-频道与启动.md) 和 [03](03-房间与模型.md)。

## 先看清楚目标形态

    Discord 手机端
         ↑↓
    Discord 服务器（一个频道 + 若干子区）
         ↑↓
    herdr.discord 插件（桥，跑在某个 herdr pane 里）
         ↑↓
    herdr server  ←—— socket——→  ~/.config/herdr/herdr.sock
         ↑↓
    若干 pane，每个 pane 里跑一个 pi 进程

关键理解：**一个 Discord 子区 = 一个 pane = 一个独立的 pi 进程**。它们互不干扰，各自有自己的会话和模型。

## 装 herdr

    brew install herdr

装完确认：

    herdr --version
    herdr session list

`session list` 能看到 `default running` 就说明 herdr server 在跑，socket 在 `~/.config/herdr/herdr.sock`。

> herdr 的真身在 `$(brew --prefix)/Cellar/herdr/<版本>/bin/herdr`，`/opt/homebrew/bin/herdr` 只是符号链接。这点在需要系统授权时很要命，见[附录](附录-踩过的坑.md)。

## 装 pi

    npm i -g @earendil-works/pi-coding-agent

agent 目录在 `~/.pi/agent/`，几个关键文件：

- `auth.json` —— 各 provider 的 API key，权限保持 600
- `settings.json` —— `defaultProvider` / `defaultModel` / `defaultThinkingLevel`
- `models.json` —— 自定义 provider 与模型（OpenAI / Anthropic / Google 兼容端点都写这里）
- `extensions/` —— pi 扩展，比如 `discord-output.ts`
- `skills/` —— 技能
- `sessions/` —— 会话记录（jsonl，一个房间一份）

## 建 Discord 机器人

到 Discord 开发者后台新建一个 Application，取 Bot 的 token。这个 token 是整套东西的命根子，只放本地。

桥需要的权限至少包括：读消息、发消息、创建公开子区、管理消息、读历史。事件订阅里要开 `MESSAGE_CREATE` 和 `THREAD_CREATE`。

## 装桥（herdr.discord 插件）

这是一个 herdr 插件，装好后由 herdr server 托管：

    herdr plugin install github:<作者>/<仓库>@<提交sha>
    herdr plugin list
    herdr plugin enable herdr.discord

插件源码会落在 `~/.config/herdr/plugins/github/herdr.discord-<hash>/`。

## 配置

桥的配置在 `~/.config/herdr/plugins/config/herdr.discord/.env`：

    DISCORD_BOT_TOKEN=<你的 token>
    DISCORD_RAW_RELAY=0
    DISCORD_AUTOSTART=1

两个开关的意思：

- `DISCORD_AUTOSTART=1` —— 新子区来消息时**自动创建 agent 并拉起 pi**。这是「在 Discord 里说话就能开工」的关键。
- `DISCORD_RAW_RELAY=0` —— 关掉桥自己的原始转发。因为 `discord-output.ts` 扩展会直接把整理好的回复发到 Discord，两边同时发会重复。

桥的状态（子区 ↔ pane ↔ agent 的映射）记在 `~/.local/state/herdr/plugins/herdr.discord/state.json`，字段形如：

    thread_id → { workspace_id, tab_id, pane_id, agent_name, kind, channel_id }

## 装 pi 扩展

把 `extensions/discord-output.ts` 放到 `~/.pi/agent/extensions/`，然后在 pi 里执行 `/reload`。

扩展装好后做三件事：

- 每条用户消息末尾追加一段输出纪律（不设字数上限、靠结构不靠砍字、禁表格等）
- 把回答里的 ```card 围栏摘出来，渲染成一张 Components V2 卡片
- 卡片底部加一条状态行：模型、上下文占比、输入输出与缓存、本次花费、余额

> 扩展里有一段「额度查询」，默认从环境变量读内部地址。不配置就不显示余额段，其余功能完整可用。

## 验证清单

按顺序过一遍：

- `herdr session list` 能看到 session 在跑
- `herdr plugin list` 里 `herdr.discord` 是 enabled
- `herdr pane list` 能列出 pane
- 在 Discord 频道里新建一个子区，随便发一句话
- 如果 `DISCORD_AUTOSTART=1`，几秒内桥会自动建 agent，`herdr agent list` 能看到新条目
- 你在子区里说话，pane 里的 pi 收到并回答

到这里环境就通了。

## 关于完全磁盘访问

如果你需要 agent 去读系统保护路径（浏览器数据、消息数据库、TCC.db 之类），就要给执行体开完全磁盘访问。

实测结论是：**给 brew 装的 adhoc 签名二进制开完全磁盘访问，很可能只在列表里出现但不实际生效**，因为 TCC 需要一个稳定可验证的代码身份。如果你必须走这条路，先确认系统设置里那条授权指向的是真实路径（`Cellar/.../bin/herdr` 而不是符号链接），并且 brew 升级换版本后授权会失效。

`scripts/ghostty_fda_restart.sh` 是当时为这件事写的重启恢复脚本，带快照、按 pane 精确恢复、逐步日志，可参考它的做法。
