# pi × Discord 桥接

在 **Discord 手机端**远程指挥本机的 **pi** 干活的一整套配置与操作。

这套东西解决的问题是：人不在电脑前，但想让本机的 agent 继续干活，并且在手机上能看懂它的回复。

## 由哪些部分组成

- **herdr** —— 终端与进程托管。提供 workspace / tab / pane / agent / session 这套抽象，让 pi 进程在关闭终端后继续活着。
- **pi** —— 编码 agent 本体。
- **herdr.discord** —— 一个 herdr 插件（桥）。把 Discord 的子区和 pane 里的 pi 一一对上，消息双向转发。
- **`discord-output.ts`** —— 一个 pi 扩展。负责把回复整理成手机可读的形态，并在每条回答后面渲染一张「结论 / 需要你」的卡片，卡片底部带状态行（模型、上下文、开销、余额）。

四者的分工一句话讲完：**herdr 管进程，pi 干活，桥传话，扩展管排版。**

## 安全提醒（重要）

这个仓库是公开的，所以：

- **Discord bot token 只放本地 `.env`，绝对不要进仓库**
- 任何内网域名、内部账号、内部工具路径都不要写进文档
- `extensions/discord-output.ts` 里的额度查询部分，内网地址已经改成从环境变量读取，不填就不显示额度段，功能其余部分不受影响
- API key 同理，放 `~/.pi/agent/auth.json`（权限 600），不要贴进任何仓库或聊天记录

## 一条经验先说在前面

这套东西里最容易踩的坑不是「怎么装」，而是 **「模型名不精确」** 和 **「进程注册表是启动时的快照」**。

前者会让你静默切到另一个供应商的同名模型，扣错钱；后者会让你改了配置却迟迟不生效。两者的细节都写在 [03-房间与模型](03-房间与模型.md) 和[附录](附录-踩过的坑.md)里。
