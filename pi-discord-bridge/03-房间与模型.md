# 03 房间与模型

新建房间、换模型、reload、查模型名。

这一篇里有两个坑，都是会**静默扣错钱**或**静默不生效**的那种，建议连坑一起看完再动手。

## 查精确模型名

    pi --list-models              # 全量
    pi --list-models mimo         # 关键字过滤

输出有 `provider` 和 `model` 两列，**两列拼起来才是完整引用**。

比如同一个 MiMo 模型，在两家供应商下的条目长这样：

    provider    model
    openrouter  xiaomi/mimo-v2.6-pro
    xiaomi      mimo-v2.6-pro

注意这两条是**两个不同的模型**，走的是**两个不同的账户**。下一节的坑就出在这。

## 换模型

对着某个 pane 发命令：

    herdr pane run <pane_id> "/model <provider>/<model_id>"

举例：

    herdr pane run w2H:p2 "/model xiaomi/mimo-v2.6-pro"

这个命令**当场生效**，也不受 agent 是否在忙的限制。可以在 pi 正在输出时发。

想在 Discord 里做同一件事，用 `!!` 前缀把命令敲进终端：

    !!/model xiaomi/mimo-v2.6-pro

启动时就指定模型，则在 `herdr agent start` 的 `--` 后面加：

    herdr agent start <name> --kind pi --pane <pane_id> -- --model provider/model_id

思考深度可以跟在冒号后：`provider/model_id:high`，可选 `off / minimal / low / medium / high / xhigh / max`。

## 坑一：同名模型跨供应商，会静默切错

这是这套东西里最值得记住的一条。

pi 解析模型引用的规则是：

- 先找规范形式 `${provider}/${id}` 精确相等的条目
- 找不到再按「第一个斜杠切开，前半当 provider，后半当 id」找
- 还找不到就退化成**只按 id 全等**找

问题在于 `openrouter` 上有个模型，它的 id 字面就叫 `xiaomi/mimo-v2.6-pro`。于是：

> 当你输入 `xiaomi/mimo-v2.6-pro`，理想情况命中 xiaomi 原厂那条
>
> 但如果 xiaomi 这个 provider 当时不在模型表里，前两步全部落空，第三步「按 id 找」就命中了 openrouter 那条
>
> 结果是**你以为在用官方 key，实际在扣 OpenRouter 余额**

现象上完全看不出来，因为两者的 model 字符串显示出来一模一样。**只有状态栏括号里的 provider 名能区分**：

    (xiaomi) mimo-v2.6-pro        ← 对的
    (openrouter) xiaomi/mimo-v2.6-pro   ← 错的

所以换完模型一定要看一眼 provider。

## 坑二：模型表是启动时的快照

pi 的可用模型表在**进程启动时**建立，依据是当时 `auth.json` 里有哪些可用凭证。

于是会发生这种事：你往 `auth.json` 里新加了一个 provider 的 key，然后去一个**早就跑着的房间**里 `/model`，它认不出这个 provider，于是掉进坑一。

解法就是让那个进程重读配置：

    herdr pane run <pane_id> "/reload"
    herdr pane run <pane_id> "/model <provider>/<model_id>"

顺序不要反。先 reload 让 provider 进表，再切模型。

## 新增一个供应商

以「官方 API、OpenAI 兼容」为例，两步。

把 key 写进 `~/.pi/agent/auth.json`：

    {
      "xiaomi": { "type": "api_key", "key": "sk-..." }
    }

然后在 `~/.pi/agent/settings.json` 里设默认：

    {
      "defaultProvider": "xiaomi",
      "defaultModel": "mimo-v2.6-pro"
    }

验证：

    pi auth check --provider xiaomi     # 期望输出 ready

如果这个 provider 是 pi 内置目录里没有的，就往 `~/.pi/agent/models.json` 的 `providers` 下加一个条目，写 `baseUrl`、`api`、`models` 三项。OpenAI / Anthropic / Google 兼容端点都能这样接。

## 开销是怎么记的

pi 按模型目录里的 `cost` 字段自动算钱，不需要你配。`cost` 形如：

    { "input": 0.435, "output": 0.87, "cacheRead": 0.0036, "cacheWrite": 0 }

单位是每百万 token。

自定义模型可以在 `models.json` 里写 `cost` 覆盖内置定价。注意**没写 cost 的模型不是免费，是没定价**，会显示 0。

DeepSeek 官方还有峰谷价，谷时是高峰的一半；pi 不区分峰谷、一律按高峰算，所以谷时会高估一倍。

## reload

    herdr pane run <pane_id> "/reload"

reload 会重载扩展、重读认证与配置。副作用是扩展里的运行时状态会被重置（比如长度上限）。

**自己 reload 自己必须延迟。** pi 在输出中会硬拒 reload，提示「等当前响应结束」。所以 agent 想给自己换扩展，得排到回合结束之后：

    nohup sh -c 'sleep 60; herdr pane run "$HERDR_PANE_ID" "/reload"' >/dev/null 2>&1 &

`$HERDR_PANE_ID` 在 agent 环境里是现成的，指它自己所在的 pane。

## 虚拟模型的 `~` 前缀

有些模型 id 本身以 `~` 开头，那是虚拟模型标记，**是 id 字面的一部分，写引用时必须带上**，不是注释也不是简写。

## 换模型后的现象

切换模型时缓存会全部失效，第一轮会看到 `Cache miss after model switch`，之后缓存命中率恢复正常。这是预期行为，不是故障。
