# 02 频道与启动

新建一个话题/频道，然后把 pi 拉起来。

## 最省事的路径：自动启动

前提是在 [01](01-环境连接.md) 里配了 `DISCORD_AUTOSTART=1`。

在 Discord 频道里新建一个子区，随便发一句话。桥收到消息后会自己建 agent、分配 pane、拉起 pi，并把你这句话投进去。

之后你在子区里说的每句话都会变成这个 pi 的输入，它的回复回到同一个子区。

> 一个子区对应一个独立的 pi 进程。所以开多个子区就是开多个互不干扰的房间。

## 想自己控制启动参数时

自动启动用的是默认模型和默认目录。如果你想指定工作目录或模型，就手动开。

先建工作区（决定 pi 的工作目录）：

    herdr workspace create --cwd /path/to/project --label "我的项目"

拿到 workspace id 后建 pane，再在 pane 上启动 agent：

    herdr agent start <agent_name> --kind pi --pane <pane_id> -- --model provider/model_id

`--` 后面的内容会原样传给 pi，所以 `--model`、`--session`、`--thinking` 这些都能带上。

想让这个房间绑定到某个 Discord 子区，就把映射写进桥的状态文件，或者直接在子区里发一句话让桥认领。

## 查看现在的房间

    herdr agent list

每个 agent 会告诉你 `pane_id`、`agent_status`、`cwd`。要更详细的：

    herdr agent get <agent_name>

`agent_session.value` 就是这个房间的会话记录文件（jsonl），排查问题时很有用。

    herdr pane list

能看到所有 pane，含 `label`、`cwd`、`focused`、`agent_session`。

## 桥的两种输入前缀

- **不带前缀** —— 正常聊天，消息作为 prompt 喂给 pi
- **`!!` 前缀** —— 把后面的内容**原样敲进终端并回车**，无视 agent 当前状态。这是给 pi 下斜杠命令的唯一可靠方式，比如 `!!/reload`、`!!/model xiaomi/mimo-v2.6-pro`
- **`!` 前缀（不是 `!!`）** —— 桥自己的命令，不进 pi

记住 `!!` 这个前缀很关键：**普通消息会被当 prompt 送给模型，只有 `!!` 才是「敲键盘」**。

## 让 pi 别刷屏

`discord-output.ts` 扩展会做这些事：

- 每条用户消息末尾自动追加一段输出纪律，从源头压住排版
- 把回答里的 ```card 围栏摘出来单独渲染成卡片
- 卡片底部加状态行

输出纪律本身是可调的，改 `extensions/discord-output.ts` 里的 `MOBILE_HINT` 数组即可。当前版本的要求是：

- 不设字数上限，讲清楚优先，但不许为省字数牺牲前提、因果、关键数字
- 可读性靠结构不靠砍字：用 `##` 小标题分节，一节只讲一件事
- 细节靠视觉分层（引用块、小字），因为 Discord 没有折叠
- 代码块只留给真正的代码、命令、原始日志
- 不用编号列表，不用表格，不用分隔线

改完记得 `/reload` 才生效。

## 回复格式约定

扩展要求 pi 每回合在正文最后输出这样一段围栏，扩展会把它渲染成卡片：

    ```card
    结论：一句话结论
    待你：需要用户做的事（没有就写「无需操作」）
    ```

围栏里允许写成 `card` / `卡片` / `小结` 任意一种。正文里不要写这个围栏以外的内容格式，扩展会自己处理。

## 常见情况

**发了消息没反应**

先看 `herdr agent list` 里对应 agent 是不是 `idle` 或 `done`。如果是 `working`，说明 pi 还在跑上一轮，消息被排队了。桥在 agent 忙时会 hold 消息，可以用桥命令看队列。

**子区被归档了**

桥只监听子区创建和消息事件，不监听归档。所以归档不会杀掉 pi 进程，它会继续在后台跑。需要它停就去终端里停掉。

**想看 pi 实际在干什么**

    herdr pane read <pane_id> --lines 100

这就是那个 pane 的屏幕内容。
