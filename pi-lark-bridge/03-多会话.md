# 03 · 多会话（一个飞书聊天里跑多个 agent）

## 要解决什么

上游的模型是「一个聊天 = 一个 pi 会话」：私聊是你，群聊是整个群，各自一个 herdr 分屏、一份历史。

想同时干两件不相关的事就不行了——比如一边让 agent 处理字幕，一边问它另一件完全不搭边的事，两件事会挤在同一条历史和同一个上下文里。`/new` 又是**销毁式**的：它会把当前历史删掉重来。

这一版把「会话」从聊天里拆出来：**一个飞书聊天可以开多个会话，每个会话是独立的 pi 会话 + 独立分屏 + 独立历史，互不干扰。**

## 命令

在飞书聊天里直接发（不用 @，私聊直接发，群里 @ 机器人再说）：

| 命令 | 作用 |
|---|---|
| `/new [标题]` | 开一个新会话并切过去；旧会话**不关**，继续活着 |
| `/list` | 列出本聊天的所有会话：编号、标题、分屏、连接状态、最后使用时间 |
| `/switch N` | 切到编号 N 的会话 |
| `/close N` | 关掉编号 N 的会话（关分屏，历史文件留在本机） |
| `/reset` | **清空当前会话**的历史并重开（上游老 `/new` 的行为，破坏性） |
| `/stop` | 中断当前会话正在跑的回合 |
| `/model [provider/id]` | 看/切当前会话的模型 |

语义上有两条是刻意的：

**一、`/new` 不再是「重来」，`/reset` 才是。** 上游 `/new` 会删历史，这里把它改名成 `/reset` 保留下来；`/new` 改成「再开一个」。这么改是因为「新建对话」和「清空对话」是两件完全不同的事，混在一个命令里迟早误删。

**二、`/new` `/switch` `/list` `/close` 立刻生效，`/model` `/reset` 排在队里。** 前者只描述或调整聊天结构——你发完 `/new` 紧接着发一句话，那句话必须进新会话；`/list` 也必须立刻回，不能排在一条可能跑十分钟的回合后面。后两者会打断或替换正在工作的会话，所以跟上游一样走 FIFO，避免在回合中间把模型换掉或把历史删掉。

## 一个聊天里，编号跟分屏怎么对应

```
会话 #1  →  key: ou_xxxx       →  herdr agent: lark-1a2b3c4d5e      →  sessions/<hash>.jsonl
会话 #2  →  key: ou_xxxx#2    →  herdr agent: lark-1a2b3c4d5e-2    →  sessions/<hash>-2.jsonl
会话 #3  →  key: ou_xxxx#3    →  herdr agent: lark-1a2b3c4d5e-3    →  sessions/<hash>-3.jsonl
```

**#1 刻意不带后缀**：老聊天的分屏名和会话文件原地不动，所以这个功能上线时，正在用的那个会话（含全部历史）不受任何影响，也不需要迁移。群聊同理，key 是 `group:<chat_id>`。

上限 8 个会话（`MAX_CONVERSATIONS`）：每个会话都是一个 herdr 分屏加一个 pi 进程，不是免费的。超了会拒绝并提示先 `/close`。

## 状态存在哪

`<项目>/.pi/lark-bot/conversations.json`：

```json
{ "version": 1, "appId": "cli_xxx",
  "chats": { "ou_xxxx": { "active": 2, "next": 3,
    "slots": [ { "id": 1, "createdAt": "…", "lastUsedAt": "…" },
               { "id": 2, "title": "字幕任务", "createdAt": "…", "lastUsedAt": "…" } ] } } }
```

两个刻意的细节：

- **只有多会话的聊天才写这个文件**。只用一个会话的聊天根本不落盘，行为与上游完全一致（有测试盯着这条）。
- **关掉的会话不再出现在编号里，编号也不会被复用**（`next` 只增不减）。所以关掉 #2 之后 `/new` 得到的是 #3，不会把别人刚关掉的历史接回来。

`/close` 不删历史文件，是为了让「关掉的分屏」还能被重新打开继续用；真要删历史用 `/reset`。

## 怎么验证

```bash
cd pi-lark-bridge
./scripts/check.sh          # 类型检查 + 单元测试，必须全绿
./scripts/deploy.sh --go    # 部署（会先跑一遍 check.sh）
```

然后重启监听（`/lark-bot off` → `/reload` → `/lark-bot on`），在飞书里：

- 发一句普通消息 → 有 ✅，有回复
- 发 `/new 第二个会话` → 回「已新建会话 #2…」
- 再发一句话 → 这一句进 #2（本机 herdr 里能看到新分屏，agent 名带 `-2`）
- 发 `/list` → 两个会话都在，`← 当前` 在 #2
- 发 `/switch 1`，再发一句话 → 回到 #1 的历史里继续
- 发 `/close 2` → #2 的分屏关掉，#1 不受影响

单元测试对应：`test/conversations.test.ts`（控制器层语义）、`test/panes.test.ts` 里「a chat's second conversation…」（分屏/命名/历史文件）。
