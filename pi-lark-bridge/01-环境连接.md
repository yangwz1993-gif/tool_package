# 01 · 环境连接

从零把飞书这条链路接起来。顺序不能乱：先有应用，再有权限，最后才是监听。

## 一、创建飞书应用

最省事的是让 pi-lark-bot 自己建，它会顺便把需要的权限和事件订阅一起勾上：

```
/lark-bot link
```

终端会画一个二维码，用**手机飞书**扫它（注意飞书分国内版 `feishu.cn` 和国际版 `larksuite.com`，扫码时选对）。扫完在手机上确认权限，应用就建好了。

也可以选「Connect an existing bot with a QR code」复用已有应用，或者手填 App ID / App Secret。本项目实测用的是**扫码新建**，建出来的应用是 `cli_aa4ca1ab8bf85bb5`。

### 注册流程在技术上做了什么

不是黑魔法，就是飞书的 device flow：

```
POST https://accounts.feishu.cn/oauth/v1/app/registration
     action=begin&archetype=PersonalAgent&auth_method=client_secret&request_user_info=open_id
  → 返回 verification_uri_complete（二维码里那个链接）、device_code
然后带着 device_code 轮询 action=poll，直到你手机上点了确认
  → 返回 app_id 与 app_secret
```

二维码里那个链接的 `addons` 参数，是一段 gzip+base64url 的 JSON，写明要申请哪些权限和事件。也就是说**扫码那一刻权限清单就定好了**，不用手工去后台一项项勾。

## 二、权限

`link` 会自动检查并告诉你缺哪些，缺就弹一个预选好的链接。目前用到的权限：

- `im:message:send_as_bot` — 发消息（回复走这个）
- `im:message.p2p_msg:readonly` — 读私聊
- `im:message.group_at_msg:readonly` — 读群里 @ 机器人的消息
- `im:message:readonly` — 读消息
- `im:message:update` — 更新卡片
- `im:message.reactions:write_only` — **贴表情回应，需要单独申请**（见 [`02-表情回应.md`](02-表情回应.md)）

申请链接形如：

```
https://open.feishu.cn/app/<APP_ID>/auth?q=<权限列表>&op_from=openapi&token_type=tenant
```

用**应用管理员**账号打开确认。别用管理员？个人账号建的应用自己就是管理员。

### 怎么在不写代码的前提下验证权限有没有生效

拿一个明显不存在的 message_id 去调目标接口，看它报的是**权限错**还是**业务错**：

- 返回 `99991672 Access denied ... scopes is required` → 权限还没开通
- 返回别的（比如 `99992354 not a valid open_message_id`）→ 权限已经过了

这招不用先拿到真实消息，很适合排查。

## 三、白名单：不批就收不到任何回复

**这是最容易卡住的一步。** 白名单为空时，机器人收到消息**不会回复内容**，只回一条拒绝提示加一个授权码。

放行有两条路：

- 在面板里执行 `/lark-bot allow`，它会列出最近被拒绝的发送者（显示 open_id、授权码、时间、消息原文），选一个回车即可
- 或者 `/lark-bot allow <open_id|授权码>` 直接指定

放行后白名单落在 `<项目>/.pi/lark-bot/allowlist.json`。

> 判断「消息到底有没有送到」看 `/lark-bot` 输出的 `Chats` 计数：它涨了说明消息进来了，`Allowlisted users` 还是 0 说明卡在白名单。

## 四、启动监听

```
/lark-bot on
```

会弹一个 `Enable remote code execution?` 的确认框。**这个开关的意思是：能私聊到机器人的人，就可以让 pi 在你本机执行代码。** 保护措施是新用户首次需要本机确认（10 秒超时，默认拒绝），且群里每个人要单独授权。它自己也会强调「所有会话共享项目文件，并非安全沙箱」。

关掉用 `/lark-bot off`（会顺手取消开机自动监听，历史保留）。

### 重启监听让新代码生效

改过扩展源码之后，光重新加载不够，按这个顺序来：

```
/lark-bot off
/reload
/lark-bot on
```

注意 `off` 会把远程执行那个开关一起清掉，所以 `on` 时会**再弹一次确认框**。

## 五、启动 herdr 会话（那个前台 Ghostty）

不要直接 `ghostty -e herdr --session lark-local`，会踩嵌套的坑。用仓库里的启动器：

```bash
open -na Ghostty --args -e /Users/yangwz/Desktop/00项目/飞书连接/pi-lark-bridge/scripts/herdr-lark-launch.sh
```

它做三件事：清掉 `HERDR_*` 让 herdr 肯启动、清掉继承来的 `PI_DISCORD_EXTENSION` 之类的上下文、然后 `exec herdr --session lark-local`。

为什么非清不可，见 [`附录-踩过的坑.md`](附录-踩过的坑.md) 第一条。

### 确认客户端真的附着了

```bash
ps -eo command | grep -E "[h]erdr --session lark-local$"
```

**没有输出 = 没有客户端附着**，此时 herdr 会用 80×40 的默认尺寸渲染，二维码下方那行链接会被裁掉，你只能靠肉眼扫屏。有输出才是正常的。

## 六、日常速查

```bash
cd pi-lark-bridge && ./scripts/status.sh --tail
```

会打出：会话状态、客户端是否附着、面板里的 agent、凭据与白名单（secret 已打码）、安装位置有没有未提交改动、以及面板最后 20 行。

## 飞书聊天里的命令

| 命令 | 作用 |
|---|---|
| `/stop` | 让 pi 中断当前操作，保留历史和分屏 |
| `/new` | 关掉当前分屏并重置历史 |
| `/model` | 查看、选择模型 |
| `/model provider/model` | 指定模型，分屏会重启 |

本机面板里的命令见上游 README，常用的有 `/lark-bot`（看状态）、`/lark-bot allow`、`/lark-bot off`。
