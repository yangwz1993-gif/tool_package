# 本地交互流程图

用户讲流程和修改意见；agent 负责语法、排版、生成与技术验收。

## 工作流程

1. 读用户提供的文档和已有模型。先列清节点、方向、判断条件、回环和节点详情；已有 ID 保持稳定。只追问影响业务含义的缺失信息。
2. 在用户工作目录保存 `model/`。新项目可复制 `assets/starter/`，修改项目名和内容。LikeC4 是可维护的源文件；HTML 是交付物。语法和布局见 [dsl-layout.md](references/dsl-layout.md)。
3. 默认首页 `index` 展示全部步骤和关系。完整不等于挤进一屏：允许大画布平移缩放。流程阶段用视图 `group` 画出带标题的边界，metadata 保留原始阶段；真实包含关系才用模型嵌套，避免为排版改变业务 ID。可额外提供概览，但不能代替完整图。
4. 模型保留完整名称、说明、条件和来源。短标题写在视图的 `include ... with` 中。优先保证阅读顺序、阶段留白和回路可追踪，再调配色；可用浅色节点、细边框、少量强调色。判断和返工保持明确区分，不要让每个步骤都成为视觉重点。
5. 根据原始需求写独立的 `expected.json`，核对完整 ID、方向和条件。不要从编译后的 JSON 反向生成预期答案。已有流程的详情也写入 `content` 以检查保真。格式见 [acceptance.md](references/acceptance.md)。
6. 运行下列构建。`OUT` 是尚不存在的版本目录；首次运行通过 npm 安装固定工具链到用户缓存，此后复用缓存。无需全局安装 LikeC4 或升级系统 Node。

```bash
python3 SKILL_DIR/scripts/build.py WORK/model \
  --expect WORK/expected.json --out WORK/releases/v1 --title '流程名称'
```

将 `SKILL_DIR` 和 `WORK` 换成实际绝对路径。脚本依赖 Python 3、npm，内置锁定 LikeC4 1.59.4 / Node 22.22.3。可用 `--runtime /path/to/toolchain` 复用具备完全相同版本的本地依赖。

7. 检查 `verification.json` 和 `exports/png/index.png`。除遗漏、穿框、重叠外，还要看阶段分区、阅读顺序、标题是否被连线干扰和留白。用户要求横向时按横向交付；自动布局仍不齐时可用原生布局快照固定对齐，见布局参考。大画布按声明的阅读缩放检查字号，同时报告缩略总览字号；不能把阅读缩放的估算说成初始页面已可读。修复后生成新版本；失败返回 2 并保留草稿和日志，不删除关系或降低字号标准来凑通过。
8. 按 [acceptance.md](references/acceptance.md) 操作浏览器验收：默认完整图、详情、缩放、复位、刷新和离线打开。使用当前环境授权的浏览器工具；访问被拒绝时遵守拒绝，继续完成独立工作，并写明哪些验收仍缺证据。用户只需最终评价是否清楚好用。
9. 交付 `flow.html` 链接、必要的预览和源目录链接。说明静态检查与实际交互验收的状态。按需附 `exports/diagrams.drawio`、SVG/PNG；无需让用户学习语法或执行构建命令。

## 持续修改

- 修改前保存源文件快照或使用版本控制。原始输入、已有交付物不覆盖。
- 区分用户要改的业务含义和显示文字。只改显示文字时，模型关系、完整说明不应改变。
- 修改相关 `.c4` 和预期文件，再构建新版本；对比模型和关系的差异，确认范围符合用户要求。只需要重测受影响行为。
- 不把导出的 draw.io 当作能无损回写的 LikeC4 源；用户转到 draw.io 手工维护时，明确以哪份为准。

## 使用边界

- LikeC4 1.59.4 没有菱形节点；用橙色和问句表达判断。需要标准 BPMN、ER、时序语法或精确手工画布时，应选相应工具。
- 优先调整原生方向、间距、同层约束和标题。需要固定对齐时，agent 可维护 LikeC4 原生 `.likec4/*.likec4.snap`；业务改变造成布局漂移时必须更新快照，不自动沿用旧图。不承诺任意图都零交叉或一屏可读。
- `static_checks_passed` 不等于浏览器验收完成。PNG/SVG 是静态预览，不能充当 HTML 截图或离线实测证据。HTML 的标签对比度须单独检查，注意浅色主题的 `mix-blend-mode` 可能冲淡颜色。
